## pars_news

Локальный парсер новостей с анализом упоминаний компаний и выгрузкой в Excel/CSV.

### Стек

- Python 3.10+
- Парсинг: `requests` + `beautifulsoup4`
- Хранение: SQLite (`sqlite3`)
- Выгрузка: `openpyxl`

### Структура

- `cli.py` — **единственная точка входа**, все команды.
- `main.py` — оркестрация парсеров (`run_all_parsers`); запуск делегирует в `cli.py`.
- `models.py` — модели новости и компании.
- `storage.py` — работа с базой данных SQLite и экспорт в CSV.
- `company_analyzer.py` — поиск упоминаний компаний в тексте новостей.
- `export_excel.py` — выгрузка результатов анализа в Excel.
- `sources/` — парсеры под конкретные сайты.
- `test_units.py` — юнит-тесты чистых функций (без сети и БД).

### Установка

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
pip install -r requirements.txt
```

### Основная команда

```bash
python cli.py collect
```

Полный цикл за один запуск: собирает всё за 7 дней из всех источников **без
лимитов**, догружает описания, размечает материалы и кладёт Excel в `exports/`.
На Windows то же самое делает двойной клик по `auto_parse_export.bat`.

Что происходит внутри и почему именно так:

1. **Сбор ссылок** — без захода в статьи, чтобы обход листингов не ждал каждую
   страницу.
2. **Догрузка описаний** — отдельным шагом, только за период отчёта.
   Прерванный прогон продолжается с того же места: шаг берёт записи, у которых
   описания ещё нет.
3. **Анализ** — упоминания компаний, тип материала, темы, кадровый сигнал.
4. **Excel** — только новости за период, а не последние N записей вперемешку
   со старыми.

Полезные параметры:

```bash
python cli.py collect --days 30              # другой период
python cli.py collect --max-pages 100        # глубже листать архивы
python cli.py collect --source rb_hr         # только один источник
python cli.py collect --no-summaries         # быстрее, но теги хуже
```

### Остальные команды

```bash
python cli.py init                                  # создать/обновить схему БД
python cli.py sources                               # список источников
python cli.py parse --days 7 --limit 200            # только собрать новости
python cli.py backfill-summaries                    # дозаполнить описания по всей БД
python cli.py analyze --export-excel --top 20       # анализ упоминаний компаний
python cli.py tags --exclude-promo                  # разметка без рекламы и анонсов
python cli.py stats --show-latest 10                # статистика по БД
python cli.py export --format both --limit 500      # выгрузка в Excel и CSV
python cli.py search --company "Газпром"            # новости по компании
python cli.py seed-companies                        # заполнить справочник компаний
python cli.py refresh-dates                         # пересчитать даты публикации
python cli.py cleanup --dry-run                     # найти в БД записи-не-новости
```

Флаг `--verbose` включает подробный лог и трассировку ошибок в консоли; в файл
`logs/` трассировка пишется всегда.

### Результаты

Выгрузки складываются в каталог `exports/` под именем вида
`Сбор новостей 07.08.2026, 20-09.xlsx` — дата и время прогона. Время пишется
через дефис, потому что двоеточие в именах файлов Windows запрещено. Метка
времени не даёт перезаписать предыдущие отчёты.

Excel-файл содержит три листа:

1. **Все новости** — весь собранный список до фильтрации по компаниям. Колонки
   «Тип материала», «Теги», «Влияние на кадры» и «Почему» позволяют отсеять
   рекламу и анонсы прямо в таблице, а «Найденные компании» пустая, если
   новость ни к одной компании не отнесена.
2. **Компании** — справочник отслеживаемых компаний (заполняется командой
   `seed-companies`; пока таблица пуста, подставляется встроенный список).
3. **Новости по компаниям** — найденные упоминания со сниппетами и той же
   разметкой.

После `collect` в файл попадают только новости за период отчёта.

#### Защита от ложных срабатываний

Названия, совпадающие с обычными словами («Самолет», «Ядро», «Контур», «Лента»,
«Магнит», «Астра», «Самокат»), перечислены в `AMBIGUOUS_ALIASES` и засчитываются
только при подтверждении контекста:

1. название в кавычках — «Лента», "Магнит";
2. слово-квалификатор слева — *застройщик* Самолет, *группа* Астра, *сеть* Лента;
3. отраслевое слово где-то в тексте — набор задаётся в `ALIAS_CONTEXT`
   (например, для «Самоката» это «доставк», «даркстор», «ритейл»).

Так «самолет вылетел с опозданием» и «ядро операционной системы» не попадают в
выборку, а «Самокат расширил экспресс-доставку» — попадает.

#### Как добавить компанию

1. Добавьте запись в `COMPANY_ALIASES` (алиасы — только в нижнем регистре, без
   повторов; латиница и кириллица перечисляются вместе).
2. Если название совпадает с обычным словом — впишите алиас в
   `AMBIGUOUS_ALIASES` и задайте для него отраслевые маркеры в `ALIAS_CONTEXT`.
3. Если компания обязательна к отслеживанию — добавьте её имя в
   `REQUIRED_COMPANIES`.
4. Перезалейте справочник в БД: `python cli.py seed-companies` (команда удаляет
   прошлые справочные записи, поэтому убранные компании не остаются в таблице).

### Даты публикации

Дата берётся только из машинно-читаемой разметки: `meta` со временем публикации,
`ld+json`, тег `time`, дата в URL, а как последнее средство — элементы с датой
внутри основного содержимого статьи. Текст страницы целиком больше не
разбирается: в шапках сайтов (например, на comnews.ru) висят часы с текущей
датой, и раньше именно они попадали в `published_at`, из-за чего в Excel у старых
новостей стояла дата сбора.

Если надёжной даты нет, поле остаётся пустым — это честнее подставленной даты.
Даты из будущего и старше 2000 года отбрасываются.

Записи, собранные до этого исправления, чинятся разово:

```bash
python cli.py refresh-dates             # только подозрительные (дата = дата сбора)
python cli.py refresh-dates --all       # пересчитать вообще все записи
```

### Источники

Полный список с числом собранных записей: `python cli.py sources`.

**Листинги** — обходятся вглубь постранично:

| Источник | Листинг | Пагинация |
|---|---|---|
| adindex | `/news/hr/` | JSON-догрузка `load_more.phtml` (даёт и точные даты) |
| comnews | `/manpower` | обычные ссылки `?page=N` |
| rbc_companies | `/news/` | параметр `?page=N` (`PAGE_PARAM`) |
| ria_companies | `/company/` | `data-url` блока «Еще», далее `data-next-url` порций |
| rb_hr | `rb.ru/tag/hr/` | `?page=N`; «Читать ещё» рисуется скриптом, разделу ~480 страниц |
| forbes_companies | `/novosti-kompaniy/` | нет — сервер отдаёт только 11 материалов |

Forbes — единственный листинг без постраничной навигации: раздел собирается
скриптом в браузере, серверная разметка содержит 11 последних материалов, и
`?page=`, RSS и sitemap раздела ничего к этому не добавляют. Его дополняет
общая лента `forbes_feed`, а накопление идёт за счёт регулярных прогонов.

Глубина обхода ограничена `MAX_PAGES` (20 страниц). Когда лента на этом не
кончается, в лог пишется «остановка на пределе в N страниц». Увеличить:
`python cli.py parse --max-pages 50`.

**Ленты RSS** — отдают заголовок, дату и лид одним запросом, листать нечего:

| Источник | Лента | Отбор |
|---|---|---|
| rb_feed | `rb.ru/feeds/all/` | вся лента |
| forbes_feed | `forbes.ru/newrss.xml` | вся лента |
| cnews | `cnews.ru` | вся лента |
| vc | `vc.ru/rss/all` | вся лента |
| frankmedia | `frankmedia.ru/feed` | вся лента |
| kommersant, vedomosti, tass, interfax, rbc_feed | федеральные ленты | только кадровые новости |

Федеральные издания пишут обо всём, поэтому к ним применяется `TOPIC_FILTER`
(`tagging.is_hr_business_news`): нужна кадровая лексика **вместе** с деловым
контекстом, а спортивные и военные сюжеты отсекаются. Без этого «назначение
пенальти» попадало бы в отчёт как кадровое движение.

**Telegram-каналы** — читаются через веб-превью `t.me/s/<канал>`, без бота и
токена. Годятся только публичные каналы с включённым предпросмотром; листаются
вглубь по `?before=<номер поста>`. У поста нет заголовка, поэтому заголовком
становится первая фраза, а полный текст идёт в лид.

| Источник | Каналы | Отбор |
|---|---|---|
| telegram_hr | 14 профильных HR-каналов | без отбора — они и так про кадры |
| telegram_business | @banksta, @if_market_news | только кадровые новости |

Профильные каналы (`telegram_hr`): @hranalitycs, @labor_market, @shl_hr_club,
@neohr, @shltools, @HR_portal, @hrtechnology, @huntflow, @friendwork,
@rff_channel, @whrdata, @hrhuballevents, @hrzarplata, @rus_hr.

Проверить канал перед подключением:

```bash
python -c "from sources.telegram import probe_channel; probe_channel('banksta')"
```

Ноль постов означает, что канал закрыт, у него выключен предпросмотр или
такого имени нет. Каналы изданий, уже подключённых через RSS, лучше не
добавлять: те же новости придут дважды под разными адресами (ссылка на сайт и
ссылка на пост), а дедупликация идёт по URL и такие пары не склеивает.

Собрать один источник: `python cli.py parse --source rb_hr`.

### Теги и разметка материалов

Разметка идёт по трём независимым измерениям — они отвечают на разные вопросы.

**1. Тип материала** (ровно один) — «что это вообще такое»:

| Тип | Признак | Кадровое событие |
|---|---|---|
| Реклама | `erid`, «на правах рекламы», промокод, скидка | нет |
| Вакансия | «мы ищем», «открыта вакансия», «присылайте резюме» | да |
| Мероприятие | вебинар, конференция, форум, «состоится» | нет |
| Обучение | курс, тренинг, интенсив, сертификация | нет |
| Исследование | исследование, опрос, респонденты, индекс | да |
| Мнение | колонка, «мнение эксперта», «мой опыт» | нет |
| Пресс-релиз | задаётся площадкой (companies.rbc.ru) | да |
| Новость | ничего из перечисленного | да |

Признак типа ищется **только в первых 180 символах**: дальше по тексту
«тренинг» и «конференция» встречаются как упоминания, а не как жанр. Без
этого ограничения аналитика «79% уволившихся назвали причиной ухода…»
становилась «Обучением» из-за Яндекс Практикума в теле текста.

Тип «Пресс-релиз» задаётся источником, а не текстом: companies.rbc.ru — это
витрина, куда компании выкладывают материалы о себе, и по тексту такой
материал от новости не отличить. Правило живёт в `SOURCE_MATERIAL_TYPES`.

**2. Тема** (сколько угодно на материал): Назначения, Сокращения, Найм и рост,
M&A, Финансы, Законодательные инициативы, Суды и санкции, Продукты и
технологии, Инциденты.

**3. Влияние на кадровые движения**: высокий / средний / нет — выводится из
тем, но гасится для рекламы, анонсов, обучения и колонок. Вебинар «как
проводить сокращения» — приглашение на вебинар, а не сокращение; ради этого
тип и отделён от темы.

```bash
python cli.py tags --exclude-promo            # без рекламы, анонсов и колонок
python cli.py tags --type Мероприятие         # только анонсы
python cli.py tags --show-signal высокий      # кадровые события
```

### Логи

Каждый запуск пишет лог в `logs/run_ГГГГММДД_ЧЧММСС.log`: в консоль идёт
INFO, в файл — всегда DEBUG со всеми трейсбеками. Прогон длинный, и без файла
сообщение об ошибке теряется вместе с окном терминала.

```powershell
Get-Content logs\run_*.log -Encoding UTF8 -Tail 40      # -Encoding UTF8 обязателен
Get-Content logs\run_*.log -Encoding UTF8 | Select-String "упал|ошибка"
```

Долгие этапы (догрузка статей, `backfill-summaries`) сообщают о прогрессе
каждые 25 записей — по этим строкам видно, что процесс идёт, а не завис.

Строка `лента закончилась на странице N` — нормальный конец раздела. А вот
`остановка на пределе в N страниц` означает, что упёрлись в `--max-pages` и
источник вычерпан не полностью.

В листингах на одну новость приходится несколько ссылок, и часть новостей
представлена только ссылкой-обёрткой вокруг картинки без текста. Заголовок для
таких ссылок берётся из атрибутов, `alt` картинки или заголовка родительского
блока — иначе новость терялась целиком.

Ранние прогоны (до появления `ARTICLE_URL_PATTERN`) успели сохранить разделы
сайтов и страницы рейтингов как новости. Найти и убрать их:

```bash
python cli.py cleanup --dry-run    # показать, что будет удалено
python cli.py cleanup              # удалить
```

### Как добавить источник

Создайте модуль в `sources/`, унаследуйте `BaseParser` и объявите:

```python
class MyParser(BaseParser):
    BASE_URL = "https://example.com"
    NEWS_URL = "https://example.com/news/"
    SOURCE_NAME = "example"

    LINK_SELECTORS = ("a[href*='/news/']",)
    ARTICLE_URL_PATTERN = re.compile(r"/news/\d+/")   # отсекает разделы сайта
```

Метод `_parse_page` реализован в базовом классе — переопределяйте его, только
если у сайта принципиально другая структура.

Если у сайта есть RSS, источник обходится дешевле — лента сразу отдаёт дату и
лид, и в статью заходить не нужно:

```python
class MyFeedParser(RssParser):
    SOURCE_NAME = "example"
    FEED_URLS = ("https://example.com/rss.xml",)
    # только для широких лент: оставить кадровые новости
    TOPIC_FILTER = staticmethod(is_hr_business_news)
```

Затем добавьте источник **в оба** места в `main.py`: в `PARSERS` (что собирать)
и в `PARSER_CLASSES` (реестр для `cleanup`). Второе обязательно: записи от
источника, которого нет в реестре, `cleanup` считает мусором и удаляет. Это
проверяется тестом `test_every_configured_source_is_in_registry`.

Проверить новую ленту, ничего не сохраняя:

```bash
python -c "from sources.rss_sources import CnewsParser as P; print(len(P().fetch(limit=20, days=30)))"
```
